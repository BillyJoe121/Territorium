# Auditoría del port visual Legalitica → Territorium React

Fecha: 26 de septiembre de 2026. Alcance: apariencia y comportamiento visual de la implementación React, contrastados con el checkout `legalitica-backoffice-front` de la rama `prod` (commit `08657bd829a64f78b9711d6ae389f77ec15faf89`). **No es una auditoría de la lógica jurídica ni del backend.** La referencia ya contiene personalizaciones de marca Territorium.

## Veredicto

El port es **parcial, no exacto**. La paleta principal, el sidebar expandido de 256 px, el topbar de 64 px, algunas sombras/radios y las familias Lato/Poppins ya se reconocen. No obstante, la cascada se interpretó mal para el fondo, faltan el rail y el drawer móvil del origen, la escala tipográfica quedó reducida, varias primitivas tienen geometría distinta y el tema oscuro actual produce contenido ilegible. La estructura de cabecera/logo/perfil también es otra. No existe una comparación visual ejecutada contra la aplicación fuente, así que no se puede certificar paridad píxel a píxel.

### Evidencia y límites

Se revisaron la [guía corregida](GUIA.md), los [50 archivos de referencia](fuente/), `src/main.tsx`, las cuatro capas CSS activas, `src/App.tsx` y componentes representativos. Se ejecutó Territorium en **modo local aislado**, sin credenciales ni llamadas de comparación reales, y se inspeccionó en Chrome a 1440, 960 y 390 px. Se probaron Comparador, Expedientes y Telemetría, además del toggle oscuro. `npm run check` pasó. No se ejecutó el checkout fuente: carece de `node_modules` y no se alteró. Tampoco se probó el flujo remoto con Supabase/worker ni cada subpantalla de un expediente.

Capturas de la ejecución auditada: [Comparador 1440](evidencia-auditoria-2026-09-26/audit-legalitica-1440.png), [Comparador 390](evidencia-auditoria-2026-09-26/audit-legalitica-390.png), [tema oscuro](evidencia-auditoria-2026-09-26/audit-legalitica-dark.png), [Expedientes 1440](evidencia-auditoria-2026-09-26/audit-legalitica-expedientes.png), [Expedientes 390](evidencia-auditoria-2026-09-26/audit-legalitica-expedientes-390.png) y [Telemetría 1440](evidencia-auditoria-2026-09-26/audit-legalitica-telemetria.png). Las capturas usan datos de demostración y **no** son capturas de Legalitica fuente.

## Camino al punto final deseado

**Definición del objetivo:** «React conserva la lógica de Territorium y reproduce fielmente el lenguaje visual efectivo del checkout fuente en las superficies acordadas, con diferencias documentadas por accesibilidad o producto». La referencia no ofrece un tema oscuro Territorium completo; decidir explícitamente si el objetivo incluye uno. Comparador, Telemetría y pantallas de expediente no tienen equivalentes 1:1 en los 50 archivos copiados: allí el objetivo viable es *consistencia con el sistema*, no copia píxel a píxel de una pantalla inexistente.

1. **Cerrar la fuente de verdad.** Mantener corregidos guía y skill; registrar paleta/cascada, componentes y capturas reales de la fuente cuando se pueda ejecutarla sin modificar su checkout. Aprobar las desviaciones obligadas por contraste y por flujos propios de Territorium.
2. **Eliminar P0.** Arreglar o desactivar tema oscuro; corregir canvas según la cascada real; resolver el color del item activo para legibilidad AA. Hacer las tres decisiones antes de propagar tokens a más pantallas.
3. **Construir los fundamentos React.** Unificar tokens primitivos → semánticos → componente, escala tipográfica de 16 px, fuentes locales y activos autorizados. Crear variantes de botón, campo, card, tabla, tab y estado en lugar de depender de overrides globales.
4. **Reconstruir el shell responsive.** Topbar, logo/perfil según la decisión de fidelidad, sidebar expandido de 256 px, rail de 75 px, drawer móvil bajo 960 px y gutters base de 24 px. Comprobar 1440, 1170, 960 y 390 px, zoom y teclado.
5. **Migrar pantalla por pantalla.** Primero una pantalla con equivalencia real (inicio/servicios, si se incluye); luego Expedientes y los subflujos, Comparador y Telemetría como adaptaciones del sistema. Para cada una, registrar fuente de sus patrones, estados y diferencias aprobadas. No sustituir diseños funcionales por una portada solo para coincidir visualmente.
6. **Verificar y estabilizar.** Comparar capturas fuente/destino con contenido y fuentes idénticos; revisar DOM/estilos calculados, contraste, foco, reducción de movimiento y ausencia de desbordes/solapes. Solo entonces retirar CSS antiguo y los `!important` redundantes.

### Criterios de aceptación propuestos

- Shell medido: 256 px expandido, 75 px rail, 64 px topbar y drawer funcional bajo 960 px, sin navegación cortada a 390 px.
- Tipografía, fondos, radios, tablas y sombras conforme al **estilo efectivo** de la fuente o con desviación aprobada por escrito.
- Ningún texto activo queda ilegible; contraste AA para texto normal y foco visible. El modo oscuro no se ofrece si no supera esta verificación.
- Comparador, Expedientes, Telemetría y las pantallas de expediente acordadas tienen revisión de escritorio/móvil y de estados vacío, lleno, cargando y error. La comparación 1:1 solo se exige donde hay pantalla fuente equivalente.
- Capturas base fuente/destino versionadas y regresión visual del shell y componentes compartidos. Sin capturas del origen, el máximo veredicto posible sigue siendo «alineado al código», no «idéntico».
- Sin imports Vue/Vuetify al build React, sin estilos globales de paquetes que deformen el shell, sin modificación del checkout `legalitica-backoffice-front`.
